# リール音声+映像 文字起こしスキル

InstagramリールのURLから、音声のナレーションと画面のテロップ(OCR)の両方を抽出し、時間軸で対応づけたExcelファイルを作る。単なる音声認識ではなく、「実際に画面に書いてある/話されている内容」を最優先で再現することが目的。

## 全体の流れ

1. 初回のみ、環境セットアップを確認する(下記「セットアップ」)
2. `scripts/transcribe_reel.py` を実行し、生データ(`timeline.csv`)を取得する
3. 生データの「内容(元データ)」列を、実際に画面に書いてある/話されている文言を最優先にしつつ、意味が通じる自然な日本語に整える(下記「整文の方法」)
4. 整えた結果を反映したExcelファイルを作り、ユーザーに渡す

## セットアップ(初回のみ確認)

以下がインストール済みであることを前提にしている。もし無ければ実行前にインストールする。

```bash
brew install ffmpeg
python3 -m venv ~/.venvs/reel-transcribe
source ~/.venvs/reel-transcribe/bin/activate
pip install yt-dlp openai-whisper openpyxl pyobjc-framework-Vision pyobjc-framework-Quartz
```

OCRはmacOS標準のVisionフレームワークを使うので、tesseract等は不要(過去にtesseractは環境依存の読み込みエラーが頻発したため採用していない)。

## 実行方法

```bash
source ~/.venvs/reel-transcribe/bin/activate
python3 <このスキルのディレクトリ>/scripts/transcribe_reel.py "<リールのURL>" --outdir /tmp/reel_<適当な識別子>
```

- `--model`: Whisperモデル。デフォルト`small`。声が不明瞭な区間は後述の方法で個別に`medium`で再認識する
- `--fps`: 映像テロップ抽出のフレームレート。デフォルト`1.0`(1秒に1枚)
- `--min-text-height`: この比率より小さい文字はOCRから除外(背景の装飾グラフィック除け)。デフォルト`0.025`

実行すると `<outdir>/timeline.csv` が生成される。列は以下の通り:

| 列名 | 内容 |
|---|---|
| 開始(秒) / 終了(秒) | 小数第一位の秒数 |
| 種別 | `音声` または `映像` |
| リンクID | 時間的に重なる音声と映像テロップに同じID(`L1`, `L2`...)を振ったもの。音声区間ごとに1つ |
| 内容(元データ) | Whisper(音声)またはVision OCR(映像)の生の抽出結果。誤字・断片化が多い |
| 内容(整文) | スクリプトの時点では元データと同じ値。次のステップで書き換える |

## yt-dlpで取得できない場合(年齢制限・ログイン必須など)

yt-dlpが失敗したら、次の順で動画を用意し、`--video` で渡す。

1. **PC画面収録(BlackHole経由)**: ログイン済みChromeでリールを開き、`scripts/record_screen.sh <outdir>/video.mp4 <リール秒数+5> [画面番号] [crop=幅:高さ:x:y]` で録画する。録画中は出力先が複数出力装置「リール録音用」(BlackHole 2ch+スピーカー)に切り替わり、終了時に自動で元へ戻る。最大音量が -60dB 未満なら警告が出るので、やり直す。初回だけBlackHoleと複数出力装置の準備が必要(未設定なら止まってユーザーに伝える)。
2. **iPhone画面収録+AirDrop**: PC経路が使えない場合にユーザーへ案内する。
3. 処理は `python3 -I scripts/transcribe_reel.py --video <動画> --outdir <outdir>` (URLは任意。キャプション・再生数・フォロワー数は動画から取れないため、ブラウザで別途読み取る)。画面収録は画質が落ちるので、OCRが読みにくい箇所は注記する。

### 画面録画フォールバックの注意(実運用で分かったこと)
- cropは画面のネイティブ解像度(例: 2880x1800)のピクセルで指定する。スクリーンショットは縮小されているため、座標を倍率(例: 2.25倍)で換算する。
- 録画中はページに触れない・シークしない(音声と映像が混ざる)。リール長の約1.8倍を録画し、きれいな1周を切り出す。
- 画面収録の許可ダイアログはユーザーに「許可」を押してもらう。macOSには`timeout`が無いので`perl -e 'alarm N; exec @ARGV'`を使う。
- 切り出した1周分の動画には `--model medium` を使い、時刻は `whisper --word_timestamps True` で細かく取る(smallだと終盤の文が欠けやすい)。
- 録画は音声と映像の時刻がずれることがある。Whisperの単語時刻とテロップを突き合わせ、区間ごとに補正して並べる(補正した旨をユーザーに伝える)。録画の先頭に前ループ末尾のテロップが残るので除外する。

## 整文の方法(最も重要な工程)

生データはOCR・音声認識特有の誤字や断片化が多く、そのままでは意味が通じない。ここをClaude自身が読み、以下の優先順位で「内容(整文)」列を書き換える。

**優先順位: ①実際に書いてある/話されている文言 > ②読みやすさ。読みやすくするための言い換えや創作は禁止。**

1. **まず生データを見て、誤字・断片化を直すだけで意味が通る場合はそれで確定する。**
   単純な誤字修正や、断片化した行を自然な順序でつなげる程度の調整にとどめる。

2. **音声が不明瞭で、生データだけでは自信が持てない場合は、実際のフレーム画像を見る。**
   `<outdir>/frames/frame_NNNN.png` (Nは`(時刻+1)`の4桁ゼロ埋め、`--fps 1`なら1枚=1秒) を読み、画面のテロップや文脈から意味を判断する。

3. **フレーム画像を見ても自信が持てない場合は、該当区間だけを高精度モデル(medium)で再認識する。**
   ただし短く切り出しすぎると文脈が失われて逆に不自然な結果になることがある(実例:「治療薬が完成します」)。まず音声全体を`--model medium`で再認識し、その中の該当区間のテキストを確認する方が精度が高い。

   ```bash
   whisper <outdir>/audio.mp3 --language Japanese --model medium --output_format json --output_dir <outdir>
   ```

4. **それでも自信が持てない場合は、絶対に文章を作らないこと。**
   「〇〇の可能性が高いが未確認」といった形で正直に伝え、ユーザーに判断してもらう。ユーザーが「テロップ(映像)を優先して」のように方針を示したら、それに従い、音声とテロップで表現が異なる旨を該当行に一言注記する(例:「(音声は『使いやすい形に』と認識されたが、テロップの表記を優先)」)。

5. **音声とテロップの内容が異なる場合、どちらが「本文」でどちらが「画面上の別の情報(ChatGPTのスクリーンショットなど)」かを区別する。**
   ChatGPTの操作画面をそのまま映しているカットでは、画面内に長いChatGPTの回答文(背景情報)と、短いテロップ本文(実際に伝えたいメッセージ)が同時に写っていることがある。この場合は整文を「【画面の○○】...背景情報.../【テロップ】...本文...」のように分けて書く。

背景の装飾グラフィック(「FILE」+ランダムな数字など、AI系動画によくある雰囲気作りの飾り)は、実際の情報ではないため整文には含めず、必要なら元データ側に残しつつ整文からは除外してよい。

## Excel出力

生データと整文の両方が揃ったら、`write_xlsx()` (scripts/transcribe_reel.py内) を使ってExcelを作る。この関数はすでに以下を行う:

- 音声の行は薄い黄色で塗る
- リンクIDが変わる境目(場面の切り替わり)に太い罫線を引く
- 上部に「音声だけの流れ」セクション、下部に「音声+映像の全体タイムライン」セクション
- E列(内容(元データ))・F列(内容(整文))は500px幅・折り返し・上揃え、A〜D列はそれぞれ90/90/60/70px、G列(キャプション)は300px
- 内容量に応じて行の高さを自動調整(全角30文字/行の目安＋余白1行。Google スプレッドシートは行の高さが不足しがちなので、余白を厚めに取っている)
- 1行目に「動画タイトル：(タイトル文字列)」、2行目に動画URL(「動画URL：」等のラベルは付けず、URLの文字列のみ)を記載し、3行目を空けてから「アカウントハンドル」以降を続ける
- シート名も同じタイトル文字列から生成(31文字上限、単語の途中で切れないよう助詞・句読点の位置で調整)。`write_xlsx()`に渡した文字列の末尾に判断根拠の注記(例:「(テロップで確認済み)」)が括弧書きで付いていても、タイトル・シート名生成時には自動で取り除く

  **タイトル文字列の決め方:** まずサムネイル(表紙)画像 (`thumbnail_path`で指定する画像) を見て、大きく表示されているタイトルのようなテキスト(例:「50代でも遅くない 今から始めたら月いくら」)があれば、それを`write_xlsx()`の`video_title`引数として渡す。L1音声が「2座」→「NISA」のように単語の途中から始まっていたり、断片的で内容が伝わらない場合は特にこちらを優先すること。表紙に明確なタイトル文字が無い場合のみ、`video_title`を省略してよい(その場合は最初の音声(L1)の整文から自動生成される)。
- G列: 「内容(整文)」(F列)の見出しと同じ行に見出し「キャプション」を置き(=内容(整文)の隣に揃う)、その次の行から`fetch_caption()`で取得した投稿本文を改行ごとに1行ずつ、重複なく配置。行番号は固定せず、実際にF列の見出しがある行を動的に検出して揃えること(セクションの上に「動画・プロフィール情報」が入るため、行番号はいつも同じにならない)
- 動画タイトルの下に「▼ 動画・プロフィール情報」として以下をこの順で記載(A列=項目名、B列=値。**太字にしない**):
  1. アカウントハンドル
  2. アカウント表示名
  3. フォロワー(アカウント全体)
  4. 投稿数(アカウント全体)
  5. (空行を1行あける)
  6. 「（リール単体）」という見出し行(この投稿だけの値であることを明示する区切り)
  7. 投稿日(この投稿単体。`fetch_video_stats()`の`upload_date`から`YYYY-MM-DD`形式で自動取得できる)
  8. 再生数(この投稿単体)
  9. 再生数/フォロワー数(`=再生数セル/フォロワー数セル` の数式。フォロワー・再生数の両方を埋めると自動計算される。**値のセルは赤字**にし、表示形式は小数点第1位まで(`0.0`)にする)
  10. いいね数(この投稿単体)
  11. いいね数/フォロワー数(`=いいね数セル/フォロワー数セル` の数式。**値のセルは赤字**にし、表示形式は%表記・小数点第1位まで(`0.0%`)にする)
  12. コメント数(この投稿単体)
  13. コメント数/フォロワー数(`=コメント数セル/フォロワー数セル` の数式。**値のセルは赤字**にし、表示形式は%表記・小数点第2位まで(`0.00%`)にする。いいね数/フォロワー数より桁を細かくしているのは、コメント数がいいね数・再生数に比べて値が小さく、小数点第1位では差が潰れて見えなくなるため)

  フォロワー・投稿数・再生数・いいね数・コメント数のセルは、桁が読みやすいよう3桁ごとに`,`区切りで表示する(`#,##0`の表示形式)。

  いいね数・コメント数は`fetch_video_stats()`(yt-dlpのメタデータ)で自動取得できる。再生数・フォロワー数・投稿数はyt-dlpでは取得できないため、`stats`辞書に値が無ければ空欄になる。ブラウザでInstagramのプロフィールページ(`/<handle>/`)を開けばフォロワー数・投稿数は比較的安定して取れる。

  フォロー獲得数・保存数(このリールがきっかけで増えたフォロー数・保存数)は検討したが、投稿者本人がInstagramのインサイト(分析)画面にログインしなければ確認できない非公開の指標で、他人のリールを外部から調査する通常のケースでは取得できないため、出力項目には含めていない。

  **再生数の取得方法(重要):**

  1. プロフィールの**「▶ リール」タブ**(`/<handle>/reels/`、またはプロフィール画面でリールアイコンのタブをクリック)を開く。デフォルトの「投稿(▦)」タブのグリッドには再生数バッジが付いていないため、必ずリール専用タブを開くこと。
  2. 対象の投稿がすぐに表示されない場合は、そのタブ上で下にスクロールして読み込む(投稿が古いほど回数が必要になる)。
  3. 個別に`find`で対象のshortcodeを検索するのではなく、**`read_page`を`filter: "all"`でページ全体に対して呼び、その出力の中から対象のリンク(`href="/<handle>/reel/<shortcode>/"`)を探す**こと。`find`はリンクのhrefテキストにはマッチしても、その前後の兄弟要素(いいね数・再生数)まで拾えないことがあり、「バッジが無い」と誤判定する原因になる(実際に一度この誤判定をした)。`read_page`全体出力では対象のリンクの直下に以下のような構造が入っている:
     ```
     link href="/<handle>/reel/<shortcode>/"
      list
       listitem
        generic "754"          ← いいね数
       listitem
      img "カウントアイコンを見る"
      generic "19万"           ← 再生数(この文字列を使う)
     ```
  4. 再生数は`"2667"`のような正確な数字の場合もあれば、`"1.9万"`や`"61万"`のように**概算表記**の場合もある。概算表記のときはそのまま概算値(`19万` → `190000`)として記録し、`write_xlsx`に渡すメモやキャプション付近で「概算」であることが分かるようにする(丸め誤差があるため、厳密な値ではないと正直に伝える)。
  5. 上記を試しても対象のリンクがどうしても見つからない(スクロールしても読み込まれない等)場合のみ、空欄にして正直にユーザーに伝えること。

  プロフィールのリール一覧グリッドで対象の投稿が見つかった場合、その投稿の**サムネイル画像(一覧に表示される見た目)**をブラウザ経由で取得し、`write_xlsx()`の`thumbnail_path`引数で貼り付けることができる。取得方法: 対象リールへのリンク要素の子要素から`background-image`のCDN URLを`javascript_tool`で取得し(`getComputedStyle(el).backgroundImage`)、そのURLを`curl`で(URLを省略せず全体を渡すこと。`_nc_ohc`等のクエリを含む署名付きURLなので一部でも欠けると"Bad URL hash"エラーになる)ダウンロードして保存する。

呼び出し方の例:

```python
import sys
sys.path.insert(0, "<このスキルのディレクトリ>/scripts")
import transcribe_reel as tr

rows = tr.build_rows(audio_events, telop_events)
# rows[i]["内容(整文)"] をここで書き換えていく(手順は上記「整文の方法」に従う)
caption = tr.fetch_caption(url)
stats = tr.fetch_video_stats(url)  # account_name/account_handle/like_count/comment_countは自動、残りは要ブラウザ調査
stats["follower_count"] = ...  # ブラウザで調べた値をここに入れる
stats["post_count"] = ...
stats["view_count"] = ...
thumbnail_path = "<curlで保存したサムネイル画像のパス、無ければNone>"
tr.write_xlsx(rows, "<出力先>.xlsx", caption=caption, stats=stats, thumbnail_path=thumbnail_path, url=url, video_title="<表紙に大きく表示されているタイトル文字。無ければ省略可>")
```

生データ→整文の書き換えをスクリプト一発で済ませることはできない(整文はClaudeが文脈判断するため)。実務上は、`build_rows()`で作った行データをPythonの変数として保持しつつ、Claudeが各行の「内容(整文)」をこのターン内で書き換えてから`write_xlsx()`を呼ぶ、という流れになる。

### サムネイルの代替取得(URL取得がブロックされた場合)
`javascript_tool`で背景画像URLを読むと「Cookie/query string data」でブロックされることがある。その場合はプロフィールの「▶ リール」タブをスクリーンショットし、対象リールの枠をffmpegで切り出して`thumbnail_path`に渡す(例: `ffmpeg -i shot.jpg -vf "crop=幅:高さ:x:y" thumbnail_<shortcode>.jpg`)。スクリーンショットはブラウザ上の表示サイズなので、座標はその画像のピクセルで指定する。元画像より粗く、再生数バッジが写り込むので、その旨をユーザーに伝える。

### 投稿日の代替取得(yt-dlpで取れない場合)
`/reel/<shortcode>/`(リールビューア)には`time`要素が無い。`/p/<shortcode>/`を開き、`javascript_tool`で`document.querySelectorAll('time')`の`datetime`/`title`属性を読むと投稿日が取れる(複数あっても同じ日付なら採用)。`stats["post_date"]`に`YYYY-MM-DD`で入れる。

## 完成したら

`SendUserFile` でxlsxをユーザーに送る。Googleスプレッドシートへのxlsxインポートは折り返し設定が引き継がれないことがあるため、その場合は「表示形式→文字の折り返し→折り返す」を手動設定するか、書式のコピー貼り付け機能を使うようユーザーに案内する。
